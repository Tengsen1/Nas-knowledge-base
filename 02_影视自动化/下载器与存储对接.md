# 下载器与存储对接

## Qbittorrent 下载器对接

### 部署 Qbittorrent

```yaml
services:
  qbittorrent:
    image: lscr.io/linuxserver/qbittorrent:latest
    container_name: qbittorrent
    restart: unless-stopped
    environment:
      PUID: "0"
      PGID: "0"
      TZ: Asia/Shanghai
      WEBUI_PORT: 8080
    volumes:
      - ./config:/config
      - <下载目录>:/downloads
    ports:
      - "8080:8080"
      - "6881:6881"
      - "6881:6881/udp"
```

### MoviePilot 中配置下载器

1. MoviePilot Web UI → 设置 → 下载器
2. 类型选择 Qbittorrent
3. 填写地址：`http://<NAS_IP>:8080`
4. 填写用户名和密码
5. 下载目录填写 QB 的下载路径（需与 MoviePilot 容器挂载的 `/downloads` 对应）
6. 保存并测试连接

### 关键陷阱：下载目录挂载

> **MoviePilot 容器必须挂载 QB 的下载目录**，否则整理功能无法读取已下载的文件。

QB 和 MoviePilot 的 `/downloads` 挂载必须指向同一个 NAS 宿主机路径，否则文件整理会失败。

### qBittorrent API 调用注意事项

- **登录接口返回 204（非 200）**：`POST /api/v2/auth/login` 成功时返回 HTTP 204，需用 `GET /api/v2/app/version` 验证登录状态
- **设置偏好需用 form-urlencoded 格式**：`POST /api/v2/app/setPreferences` 必须用 `application/x-www-form-urlencoded` 传 `json` 参数
- **做种优化配置**：`max_uploads=100`、`max_uploads_per_torrent=20`、`max_connec=1000`、`max_connec_per_torrent=200`、分享率和做种时间设为无限制（`-1`）
- **通过 URL 批量添加种子**：`POST /api/v2/torrents/add` 的 `urls` 参数支持多个 URL（换行分隔）
- **qBittorrent v5 API 变更**：登录返回 204 + cookie（`QBT_SID_8080`），RSS 端点有变化

## 115 网盘存储对接

### 配置流程

1. MoviePilot Web UI → 设置 → 文件管理
2. 选择存储类型：115 网盘
3. 点击 OAuth 授权，跳转 115 网盘登录页面
4. 登录 115 网盘完成授权
5. 设置媒体库根目录（如 `/Tengsen's Videos/`）

### 整理方式配置

| 配置项 | 说明 | 推荐值 |
|--------|------|--------|
| 整理方式 | 移动 / 复制 / 软链接 | **复制（copy）**（保号场景）或 移动（节省空间） |
| 自动整理 | 下载器监控 | 开启 |
| 资源目录 | 115 网盘媒体根目录 | 如 `/Tengsen's Videos/` |

### 关键陷阱：115 网盘不是下载器

> **115 网盘在 MoviePilot 中是"文件存储"模块，不是下载器。** 下载必须通过 QB/Transmission/Rtorrent 完成，然后由 MoviePilot 整理转存到 115 网盘。

## 下载目录存储路径迁移

当做种文件积累导致磁盘空间不足时，需将 QB 下载目录迁移到更大容量的磁盘。

**迁移步骤**：

1. **修改 QB docker-compose.yml**：将 `/downloads` 挂载指向新的大盘路径
2. **修改 MoviePilot docker-compose.yml**：同步更新 `/downloads` 挂载指向同一新路径
3. **迁移现有种子文件**：`cp -a <旧路径>/* <新路径>/`
4. **重建 QB 容器**：`docker rm -f qbittorrent && docker compose up -d`
5. **重建 MoviePilot 容器**：同样 `docker rm -f && docker compose up -d`
6. **验证**：检查 QB 中种子状态，确认 MoviePilot 能正常整理转存
7. **清理旧目录**：确认正常后删除旧下载目录

> **关键陷阱**：QB 和 MoviePilot 的 `/downloads` 挂载必须指向同一个宿主机路径。
